# 06 막혔을 때

## 언제
같은 실패가 두 번 나왔을 때, AI의 "완료"를 믿기 어려울 때, 시간이 예상의 두 배를 넘겼을 때, Browser에서 버그를 발견했을 때. 이 파일은 상황을 보고 하나만 고릅니다.

## 프롬프트

### A. 같은 실패가 두 번 (증상이 있을 때)

```
$systematic-debugging 증상:
"""
<출력이나 에러 그대로 붙여넣기>
"""
먼저 재현 명령을 만들어서 실제로 재현해. 원인이 확인되기 전에는 코드를 고치지 마. 가설은 둘 이하로, 각각 확인 방법을 한 줄씩.
```

해결되면 기록합니다.

```
$collab-log 방금 건을 기록해. 증상, 재현 명령, 원인(확인된 것만 확인된 것으로), AI 제안, 내 판단(채택/수정/폐기)과 이유, 확인 명령과 결과, 커밋 해시.
```

### B. AI가 "고쳤다"고 했는데 증거가 없을 때

```
고쳤다고 한 부분을 지금 다시 실행해서 증거를 보여줘. 실행한 명령과 출력, 통과한 테스트 이름. 실행하지 않은 것은 '미실행'이라고 써.
```

### C. Browser에서 버그를 발견했을 때

```
Browser에서 발견한 문제: <증상, 주소, 조작 순서>
$e2e 먼저 이 문제를 재현하는 단계를 scripts/e2e.py에 추가하고 실패하는 것을 보여줘. 그다음 최소 수정으로 고치고 같은 단계가 통과하는 것을 보여줘.
사건은 $collab-log로 기록해(발견: 사용자).
```

### D. Codex가 패키지 설치나 외부 접속을 시도할 때 (Esc로 끊은 뒤)

```
패키지 설치와 외부 네트워크는 금지야. preflight 결과에 있는 것과 표준 라이브러리만으로 대안을 제시해. 대안이 없으면 이 기능을 '안 할 일'로 옮길 때의 영향을 세 줄로 알려줘.
```

### E. 시간이 예상의 두 배를 넘었을 때

```
남은 시간 <N>분, 기능 동결까지 <M>분이야. 지금 슬라이스를 계속할 때와 범위를 줄일 때를 비교해줘.
줄일 수 있는 최소 범위, 그때 충족되는 R번호와 못 하는 R번호, 필요한 문서 변경(안 할 일, 알려진 한계). 결정은 내가 해.
```

### F. 구현이 합의와 다르게 흘러갈 때

```
TASK.md '합의' 칸을 기준으로 지금 구현과 어긋난 부분만 찾아줘. 어긋남마다 합의의 어느 문장인지 인용하고, 고칠지 합의를 담당자에게 다시 확인할지는 내가 정할게.
```

## 정상이면
1. 원인이 확인된 뒤에 수정이 시작됩니다(가설 단계에서 코드를 건드리지 않습니다).
2. 사건 기록에 재현 명령과 확인 결과가 있습니다.
3. 포기한 범위는 TASK.md '안 할 일'과 DECISIONS에 이유와 함께 남았습니다.

## 아니면

AI가 가설만 계속 늘어놓을 때:

```
가설 말고 확인한 사실만 말해. 지금까지 실행해서 확인한 것 / 확인하지 못한 것 / 다음에 실행할 명령 하나.
```

수정을 두 번 시도해도 안 될 때는 멈추고 범위를 줄입니다(E). 시간을 더 쓰기 전에 [S1-handoff](S1-handoff.md)로 현재 상태를 저장해 두면 새 세션이 새 눈으로 볼 수 있습니다.
