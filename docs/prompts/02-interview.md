# 02 담당자 인터뷰 (interview)

## 언제
약 20분(19:20~19:40). 담당자 AI에게 **제가 직접** 질문을 보내고 답을 받습니다. Codex는 질문 문구를 만들고 답을 TASK.md에 반영합니다. 20분을 넘기면 남은 질문은 가정으로 돌립니다.

담당자는 구체적인 질문에만 잘 답하는 경향이 있습니다. 해법 단어(웹앱, 최적화 등)를 먼저 꺼내지 말고 상황과 숫자로 묻습니다.

## 프롬프트

### 1. 질문 설계 (처음 한 번)

```
$interview 질문 계획부터 세워줘. 아직 보내지 말고 표만 만들어.
질문 번호 | 한 줄 목적 | 답에 따라 바뀔 완료 조건 R번호 | 복사용 질문 문구

순서는 '곤란했던 일 → 현재 임시방편 → 횟수·규모 → 사용자·역할 → 이번에 할 것/안 할 것 → 경계·예외'로 해.
6~10개. 답이 구현을 바꾸지 않는 질문은 넣지 마. 한 질문에 사실 하나만 물어.
```

### 2. 답변 반영 (답을 받을 때마다 반복)

```
담당자 답변 원문:
"""
<붙여넣기>
"""

TASK.md에 반영하고 이렇게만 보고해.
- 확정된 사실 (한 줄씩)
- 아직 모호한 부분
- 바뀐 완료 조건 R번호
- 다음에 보낼 질문 하나 (복사용)
```

### 3. 마무리 (20분이 됐거나 질문이 소진됐을 때)

```
남은 질문은 가정으로 돌리고 가정마다 근거를 적어. 그다음 합의문을 복사용으로 만들어줘.
문제 / 만들 것 / 만들지 않을 것 / 성공 기준 / 제약 — 각각 1~3줄.
가정이 섞이면 '가정:'을 붙여서, 담당자가 맞는지 틀린지 바로 답할 수 있게 해.
```

### 4. 합의 기록 (담당자가 확인해 준 뒤)

```
담당자 확인: "<답변 원문>"
TASK.md '합의'에 시각과 함께 기록하고, 정정된 부분이 있으면 완료 조건 R번호를 고쳐. 끝나면 'docs: 계약서와 합의'로 커밋하고 바뀐 R번호만 알려줘.
```

## 정상이면
- 답을 받을 때마다 TASK.md의 '사실' 또는 '가정'이 실제로 바뀌었습니다.
- 질문이 서로 겹치지 않고, 앞 답에서 나온 숫자나 용어를 다음 질문이 이어 받습니다.
- 합의문의 '만들지 않을 것'이 비어 있지 않습니다(범위가 정해졌다는 신호).

## 아니면

답이 README를 그대로 되풀이할 때:

```
방금 답은 README 내용을 되풀이했어. README에 없는 숨은 조건만 겨냥해서, 같은 주제를 더 구체적인 질문 둘로 바꿔줘. 가능하면 예시 상황이나 숫자를 넣어서.
```

물어볼 거리가 막막할 때:

```
README와 TASK.md만 보고, 구현에서 결과가 갈릴 만한 숨은 조건을 유형별로 하나씩 후보로 뽑아줘: 경계값(같으면 포함인가), 예외 우선순위, 단위·시간대, 결측·중복, 용어 정의, 역할별 권한, 동시 요청. 해당 없는 유형은 건너뛰어. 후보마다 질문 한 문장.
```

담당자가 응답하지 않거나 장애일 때는 가정으로 진행합니다.

```
담당자 응답이 없어서 열린 질문을 전부 가정으로 돌릴게. TASK.md에 '미확인'으로 표시하고, 가정이 틀렸을 때 가장 크게 바뀌는 구현 3가지를 알려줘.
```
