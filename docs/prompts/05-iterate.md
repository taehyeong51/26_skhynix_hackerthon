# 05 슬라이스 반복 (slice)

## 언제
80~140분. 슬라이스 하나가 20~30분을 넘지 않게 돌립니다. 슬라이스마다 "구현 → 제가 이해했는지 확인 → 기록" 순서를 지키면 서술형 재료가 그대로 쌓입니다. 이 단계에서 제가 가장 많이 쓰는 프롬프트는 1번과 3번입니다.

## 프롬프트

### 1. 슬라이스 하나

```
$slice <R번호> <슬라이스 이름>.
기대 동작: <입력 → 출력 또는 화면 한 줄>
확인 명령: <명령 또는 테스트 이름>
수정 가능 범위: <파일/폴더> (그 밖은 건드리지 마)

테스트를 먼저 실패시키고, 통과하면 커밋해. 끝나면 변경 요약 3줄과 실행 출력만 보여주고 멈춰.
```

### 2. 핵심 동작의 실패 경로

```
$slice <핵심 동작>의 실패 경로. FAILURE_MODES.md 표를 기준으로 '중복·동시 요청', '제약 불충족', '내부 실패' 세 경로를 각각 테스트로 먼저 만들어 실패시킨 뒤 구현해.
세 경로 모두 '기존 적용 결과가 보존되는지'를 단언에 넣어. 표의 '확인한 테스트' 칸은 테스트 이름으로 채워.
```

### 3. 내가 설명할 수 있는지 확인 (의미 있는 슬라이스 뒤에)

```
방금 변경을 내가 설명할 수 있게 다섯 줄로 정리해줘.
무엇을 / 왜 이 방식인지 / 어디서 깨질 수 있는지(구체적인 입력) / 어떻게 확인했는지(명령) / 버린 다른 방법과 이유
새 코드를 쓰지 말고, 설명이 안 되는 부분은 '모름'이라고 써.
```

이어서 기록합니다.

```
위 내용을 DECISIONS.md에 한 항목으로 남겨. '기대는 가정'과 '가정이 깨지는 입력'은 비워 두지 마.
```

### 4. 재사용·캐시·최적화를 넣었을 때

```
방금 추가한 재사용(또는 캐시·최적화)이 기대는 가정을 말해줘. 그 가정이 깨지는 입력을 하나 만들어서 결과가 틀려지는지 테스트로 확인하고, 전체를 다시 계산하는 쪽으로 돌아가는 장치가 있는지도 보여줘.
```

### 5. 문서 갱신 (슬라이스 2~3개마다)

```
커밋 이력과 실제로 돌려 본 명령만 근거로 HOW_TO_USE.md의 '실행 방법'과 '구현 범위' 표를 최신으로 고쳐줘. 돌려 보지 않은 것은 쓰지 마.
```

## 정상이면
1. 커밋 메시지에 R번호가 있고, 본문에 `확인: <명령> -> <결과>`가 있습니다.
2. 변경 파일이 "수정 가능 범위" 안에 있습니다.
3. 3번의 다섯 줄을 읽고 제가 다시 말할 수 있습니다. 못 말하겠으면 그 기능은 넣지 않습니다.
4. DECISIONS에 "기대는 가정"이 비어 있지 않습니다.

## 아니면

요청한 범위를 벗어났을 때:

```
이 슬라이스에서 읽은 파일과 바꾼 파일을 모두 나열해. 요청 범위를 벗어난 변경이 있으면 이유를 말하고, 되돌릴지는 내가 정하게 해줘.
```

코드가 필요 이상으로 커질 때(core 설치 시):

```
$ponytail 방금 변경에서 요구에 없는 부분을 걷어내고, 같은 확인 명령이 통과하는 가장 작은 변경으로 다시 제안해. 적용은 내가 승인한 뒤에.
```
