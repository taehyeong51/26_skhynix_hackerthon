# S1 인계와 재접속

## 언제
컨텍스트가 길어져 앞 내용을 잊거나 응답이 느려질 때, 접속이 끊겼다 돌아왔을 때, 새 세션으로 이어가고 싶을 때. 시간을 아끼려면 컨텍스트가 길어지기 전(약 100분)에 한 번 저장해 둡니다.

## 프롬프트

### 1. 상태 저장

```
docs/HANDOFF.md를 지금 상태로 갱신해.
완료(확인된 R번호와 근거 명령) / 진행 중 / 미실행·미확인 / 핵심 결정(DECISIONS 항목 번호만) / 다음 할 일 순서 / 실행 방법 / 깨지기 쉬운 곳
대화 내용을 옮기지 말고 파일 경로와 커밋 해시로 가리켜. 끝나면 커밋해.
```

### 2. 새 세션에서 이어가기

```
docs/HANDOFF.md → docs/TASK.md → git log --oneline -10 순서로 읽어.
읽은 뒤에 현재 상태 세 줄과 다음에 할 일 하나만 말하고 멈춰. 아직 아무것도 실행하지 마.
```

### 3. 접속이 끊겼다 돌아왔을 때

```
접속이 끊겼다 돌아왔어. git status와 git log -3을 보여주고, 끊기기 직전 작업이 커밋됐는지 확인해.
커밋되지 않은 변경은 내용을 요약하고 되살릴지 버릴지 내가 정하게 물어. 서버가 떠 있었다면 포트 상태도 확인해줘.
```

## 정상이면
1. 새 세션이 말한 상태 세 줄이 제가 아는 상태와 같습니다. 다르면 HANDOFF가 잘못 쓰인 것이니 바로 고칩니다.
2. 다음 할 일이 하나로 정해져 있습니다.
3. 커밋되지 않은 변경이 누락 없이 보고됩니다.

## 아니면

HANDOFF가 대화 요약처럼 길어졌을 때:

```
HANDOFF.md를 처음 보는 사람이 2분 안에 읽을 길이로 줄여줘. 코드나 대화는 빼고, 파일 경로·커밋 해시·명령으로 가리켜. 줄이면서 '다음 할 일'과 '깨지기 쉬운 곳'은 남겨.
```

끊긴 시각과 증상은 시험 환경의 문의 버튼으로 접수합니다. 타이머 정지나 시간 연장이 자동으로 인정된다고 가정하지 않습니다.
