# 01 계약서 (kickoff)

## 언제
설치 직후부터 약 15분. Codex가 정리하는 동안 **제가 과제 README를 직접 읽습니다**(AI 요약만 믿지 않습니다). 이 단계에서 코드를 쓰면 안 됩니다.

## 프롬프트

```
$kickoff 시작 <HH:MM>, 과제 마감 <HH:MM>, 기능 동결 <HH:MM>.

이번 턴은 읽기와 정리만 해. 코드, 패키지 설치, 서버 실행은 하지 마.
- 과제 README와, README가 가리키는 파일만 읽어. 데이터 파일은 앞부분만.
- docs/TASK.md는 README에 문장이 있는 것만 '사실'로 쓰고 출처 위치를 붙여. 나머지는 '가정'이야.
- 열린 질문은 결과를 바꾸는 것만 남기고, 질문마다 영향받는 완료 조건 R번호를 붙여.
- 필수 산출물의 이름과 위치가 README에 있으면 그대로 옮겨 적어.

끝나면 아래 형식으로 보고하고 멈춰.
과제 한 줄 요약 / 완료 조건 개수 / 열린 질문 상위 5개 / 필수 산출물 경로
```

## 정상이면
1. 한 줄 요약이 제가 읽은 과제와 같습니다.
2. '사실' 항목에 모두 README 근거 위치가 있습니다.
3. 필수 산출물 경로가 README와 같습니다(다르면 뼈대 파일 위치부터 맞춥니다).
4. 열린 질문이 "답에 따라 구현이 달라지는 것"입니다. 취향이나 구현 방식 질문은 빼야 합니다.
5. 완료 조건이 확인 가능한 문장입니다("잘 동작한다"는 아닙니다).

## 아니면

'사실'에 근거가 없어 보일 때:

```
TASK.md '사실' 항목마다 README의 근거 문장을 따옴표로 인용해. 인용하지 못하는 항목은 '가정'으로 옮겨.
```

요구사항이 빠진 것 같을 때:

```
README를 다시 읽고, TASK.md에 없는 요구사항·제약·수치·용어만 목록으로 알려줘. 이미 있는 것은 반복하지 마. 파일은 아직 고치지 마.
```

README가 문제를 거의 정해 주지 않을 때:

```
README가 문제를 거의 정해 주지 않아. 담당자에게 먼저 물어야 할 것을 결과에 미치는 영향이 큰 순서로 8개 이하로 정리해. 질문마다 '답에 따라 달라지는 구현'을 한 줄로 붙여.
```
