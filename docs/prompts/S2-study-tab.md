# S2 공부 에이전트 (문제 이해, 풀이 이해, 서술형 대비)

## 언제
Codex가 오래 도는 동안 제가 놀지 않고 이해를 쌓는 용도입니다. 에이전트 대기 시간이 긴 순서는 대략 `$slice` 반복 > 첫 E2E > `$e2e` > `$verify` > `$plan`입니다(추정, 리허설에서 재 보세요). 담당자 AI 답을 기다리는 인터뷰 구간도 쓸 수 있습니다.

| 시점 | 목적 | 프롬프트 |
| --- | --- | --- |
| 인터뷰 답 대기, `$plan` 실행 중 | 문제 이해 | 1번 |
| `$slice`, 첫 E2E, `$e2e` 실행 중 | 현재 풀이 이해 | 2번 |
| 중간 점검 이후, 동결 후 | 서술형 대비 | 3번 |

역할은 읽기 전용 학습 보조입니다. 구현을 맡기는 것이 아닙니다.

## 둘째 탭으로 쓸지, 서브에이전트로 쓸지
| 방식 | 좋을 때 | 주의 |
| --- | --- | --- |
| **둘째 탭** | 질문하고 내가 답하고 평가받는 왕복(2번 뒤 질문, 3번 전체) | 같은 작업 폴더와 git을 보는지 먼저 확인 |
| **서브에이전트** | 한 번에 끝나는 설명·질문 목록 만들기 | 결과가 메인 대화에 쌓여 컨텍스트가 늘고, 왕복에는 맞지 않음 |

시험장 Codex에서 서브에이전트를 쓸 수 있는지는 확인하지 못했습니다. 안 되면 탭으로 갑니다.

## 규칙 (모든 프롬프트 공통)
- **읽기 전용.** 파일 수정, 커밋, 서버 실행을 하지 않습니다. 메인 탭과 같은 폴더를 보기 때문입니다.
- **커밋된 상태만 읽습니다.** 작업 중인 파일은 반쯤 바뀐 상태일 수 있습니다. `git show HEAD`, `git ls-files`로 읽게 합니다.
- **답을 대신 써 주지 않습니다.** 질문하고, 제 답을 평가하고, 빠진 곳을 지적합니다.
- **문서 반영은 메인 탭에서만.** 공부 에이전트가 틀린 문장을 찾으면 제가 메인에 전달합니다.
- **서술형 시간에는 쓰지 않습니다.** AI와 복사·붙여넣기가 금지입니다.
- **출력은 짧게.** 토큰 사용량이 평가 참고 대상입니다.

## 프롬프트

### 0. 탭 확인 (둘째 탭을 처음 열 때, 1분)

```
읽기 전용으로 아래만 확인해서 한 줄씩 답해. 아무것도 수정하지 마.
1. pwd 와 git rev-parse --show-toplevel
2. git status --short 와 git log --oneline -3
3. 인식된 스킬 이름 목록
```

메인 탭과 폴더·커밋이 같으면 정상입니다. 다르면 이 탭은 쓰지 않고 서브에이전트 방식으로 갑니다.

### 1. 문제 이해 (인터뷰·계획 중)

```
너는 읽기 전용 공부 도우미야. 파일 수정, 커밋, 서버 실행은 하지 마. 읽을 곳은 과제 README, docs/TASK.md, docs/SCREENS.md뿐이야.
과제를 처음 듣는 사람에게 설명하듯 다섯 줄로 요약해줘: 누가 / 무슨 문제 / 지금 방식의 불편 / 이번에 만들 것 / 만들지 않을 것.
그다음 내가 이해했는지 확인하는 질문 세 개만 만들어줘. 답은 알려주지 말고 내 답을 기다려.
```

### 2. 현재 풀이 이해 (슬라이스가 커밋될 때마다)

```
읽기 전용이야. 파일 수정, 커밋, 서버 실행은 하지 마. 읽을 곳은 `git log --oneline -5`, `git show HEAD`의 변경 내용, docs/DECISIONS.md, docs/FAILURE_MODES.md야. 작업 중인 파일은 읽지 말고 커밋된 상태만 봐.
방금 커밋된 변경을 나에게 설명해줘: 무엇을 했나 / 왜 이 방식인가 / 어디서 깨질 수 있나(구체적인 입력) / 어떤 명령으로 확인했나.
설명 뒤에 내가 답해야 할 질문 두 개를 던지고, 내가 답할 때까지 정답을 알려주지 마.
```

서브에이전트로 쓸 때(메인 탭에서):

```
서브에이전트 하나를 읽기 전용으로 띄워서 방금 커밋(git show HEAD)을 설명하게 해. 파일 수정, 커밋, 서버 실행은 금지야. 돌려줄 것은 다섯 줄 설명과 내가 답할 질문 두 개뿐이야. 너는 그동안 다음 슬라이스를 계속 진행해.
```

### 3. 서술형 대비 (동결 후, 제출 전)

```
읽기 전용이야. 읽을 곳은 AI_COLLABORATION.md, HOW_TO_USE.md, docs/DECISIONS.md, docs/FAILURE_MODES.md, git log, 핵심 동작의 코드야.
이 산출물만 보고 심사자가 물을 만한 서술형 질문을 네 유형에서 하나씩 만들어줘: 구현 범위와 검증 경로 / 핵심 동작의 실패 경로 / 최적화가 기대는 가정이 깨지는 조건 / AI 협업 사건 하나.
질문을 하나씩 내고, 내 답을 받으면 '구체적인 약점 → 파급 → 다음에 확인할 것' 기준으로 부족한 점만 짚어줘. 모범 답안은 써주지 마.
내 답이 문서나 코드와 어긋나면 어느 파일 몇 번째 줄인지 알려줘.
```

## 정상이면
1. 설명에 파일 이름, 함수 이름, 실제 명령이 나옵니다. 일반론이 아닙니다.
2. 질문이 제 산출물에서 나옵니다("일반적인 질문"이면 다시 만듭니다).
3. 제가 답하기 전에는 정답을 말하지 않습니다.
4. `git status`가 공부 에이전트 때문에 바뀌지 않았습니다.

## 아니면

공부 에이전트가 파일을 고치려 하거나 답을 먼저 써 줄 때:

```
멈춰. 너는 읽기 전용이고 답을 대신 쓰지 않아. 방금 한 변경은 되돌릴 필요가 있는지 git status로만 보여주고, 질문 하나로 다시 시작해.
```

설명이 코드와 맞지 않아 보일 때:

```
방금 설명에서 근거가 되는 파일과 줄 번호를 각 문장마다 붙여줘. 근거를 못 대는 문장은 '추측'이라고 표시해.
```

메인 탭과 폴더가 다를 때는 이 방식을 쓰지 않고, 공부가 필요할 때마다 메인에서 서브에이전트로 한 번씩 맡깁니다.
