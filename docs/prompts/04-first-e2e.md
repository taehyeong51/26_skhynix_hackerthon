# 04 최소 E2E와 화면 확인 (slice, e2e)

## 언제
약 30분(19:50~20:20). 목표는 기능이 많은 앱이 아니라 **제출 가능한 최소본**입니다. 입력에서 핵심 규칙을 거쳐 출력까지 한 번 돌고, 그 결과를 **제가 직접 Browser에서** 봅니다. 80분이 지나도 안 되면 [06-stuck](06-stuck.md)의 범위 축소를 씁니다.

## 프롬프트

### 1. 최소 E2E 구현

```
$slice 첫 슬라이스(최소 E2E). 서버는 0.0.0.0:<포트>.
시작 전에 기대값(구체적인 입력 → 출력)과 확인 명령을 3줄로 쓰고, 테스트를 먼저 실패시켜.
이번 슬라이스에서 하지 말 것: 계획에 없는 화면, 옵션, 스타일링.
확인은 실행 결과로만 해. 서버를 띄운 뒤 첫 화면 응답과 핵심 흐름 한 번을 명령으로 보여줘.

끝나면 커밋하고 이렇게 보고해.
실행한 명령과 출력 핵심 / 아직 돌려 보지 않은 것 / 내가 Browser에서 확인할 주소와 테스트 계정
```

### 2. 제가 Browser에서 확인할 것 (프롬프트 아님)
- 로그인 성공, 잘못된 비밀번호
- 역할별로 보이는 화면과 버튼, 다른 역할 주소를 직접 입력했을 때
- 새로고침 후 상태 유지
- 빈 값과 이상한 형식 입력
- 핵심 버튼 연타

### 3. 확인 결과 전달

```
Browser 확인 결과:
- 로그인: <OK / 문제 설명>
- 역할별 화면·권한: <…>
- 새로고침 후 상태: <…>
- 잘못된 입력: <…>
- 핵심 버튼 연타: <…>

문제가 있으면 $collab-log로 한 건씩 기록해(발견: 사용자). 그다음 영향이 큰 순서로 고칠 순서만 제안하고, 고치는 건 내가 정한 뒤에 시작해.
```

### 4. 확인한 흐름을 자동화 (Playwright가 있을 때)

```
$e2e 방금 내가 손으로 확인한 흐름을 scripts/e2e.py 시나리오로 옮겨줘.
선택자는 실제 화면(page.content나 스크린샷)에서 확인하고 추측하지 마. 기대값은 화면 문구나 개수처럼 구체적으로.
실행해서 PASS/FAIL 줄을 그대로 보여줘. Playwright나 브라우저가 없으면(exit 3) 설치하지 말고 알려줘.
```

### 5. 이정표

```
최소 E2E와 화면 확인이 끝났어. git status를 보여주고, 변경이 있으면 커밋한 뒤 m1-e2e 태그를 붙여.
```

## 정상이면
1. 테스트가 먼저 실패했다가 통과한 출력이 보입니다.
2. 서버 응답을 실제 명령으로 확인했습니다("될 것이다"는 아닙니다).
3. 보고에 "아직 돌려 보지 않은 것"이 비어 있지 않고 솔직합니다.
4. 제가 Browser로 본 결과가 AI 설명과 일치합니다.

## 아니면

서버가 Browser에서 안 열릴 때:

```
Browser에서 http://<주소>:<포트>가 열리지 않아. 서버가 0.0.0.0에 바인딩됐는지, 포트가 맞는지, 이미 쓰는 포트가 아닌지를 명령으로 확인하고 결과만 보여줘. 원인이 확인되기 전에는 코드를 고치지 마.
```

첫 슬라이스가 너무 커졌을 때:

```
이 슬라이스가 예상보다 커졌어. 지금까지 된 것과 안 된 것을 구분하고, 핵심 흐름 한 줄기만 돌리는 가장 작은 범위로 줄이면 무엇을 빼야 하는지 알려줘. 결정은 내가 해.
```
