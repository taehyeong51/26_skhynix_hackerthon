# 09 제출 마무리 (wrapup)

## 언제
동결 후 약 25분(21:25~21:50). 제출 확정을 마지막에 몰지 않습니다. 순서는 문서 확인 → 제출물 경계 확인 → 설명 연습 → 제출 확정입니다. 제출 확정 뒤에는 AI를 쓰지 않습니다. 서술형 질문은 제 산출물에서 만들어지므로, 문서에 적힌 문장은 모두 사실이고 제가 설명할 수 있어야 합니다.

## 프롬프트

### 1. 마무리

```
$wrapup 제출 마무리야.
- HOW_TO_USE.md에 적힌 실행 명령을 지금 실제로 하나씩 돌려서 맞는지 확인하고, 틀린 건 고쳐.
- AI_COLLABORATION.md 사건 로그를 git log와 대조해. 사실과 다른 문장은 먼저 보여주고, 고쳐도 되는지 내게 물어.
- 제출물에 섞이면 안 되는 파일(키트 원본, 임시 파일, 비밀값, 큰 데이터 복사본)이 없는지 git status와 파일 목록으로 확인해.
- 끝나면 'docs: 제출 문서 마무리'로 커밋하고 submit 태그를 붙여.
셀프 질문 6개는 맨 마지막에 만들어줘.
```

### 2. 처음 보는 사람의 시선으로 점검 (별도 세션)

```
처음 보는 사람으로서 HOW_TO_USE.md만 읽고 서비스를 실행해 봐. 문서대로 되지 않는 지점과, 문서에 적혀 있지 않은 전제만 보고해. 코드는 수정하지 마.
```

### 3. 설명 연습 준비

```
셀프 질문 6개에 답 골격만 붙여줘. 완성된 답안은 쓰지 마.
골격: 무엇을 만들었나 → 왜 그렇게 했나 → 어디서 깨질 수 있나 → 어떻게 확인했고 무엇을 더 확인할까.
질문은 내 산출물에서 나와야 해: 구현 범위와 제외, 핵심 동작의 실패 경로, 최적화가 기대는 가정, AI 협업 사건 하나, 설계 이유 하나, 다음 개선 하나.
```

## 제가 할 일 (프롬프트 아님)
1. **제출 미리보기에서 확인합니다.** 소스, AI_COLLABORATION.md, HOW_TO_USE.md가 모두 포함되고, 키트 원본이나 숨은 폴더가 섞이지 않았는지 봅니다. 숨은 폴더가 자동 제외된다고 가정하지 않습니다.
2. **셀프 질문 6개에 소리 내어 답합니다.** 핵심 동작 하나의 흐름을 함수 이름까지, 사건 로그 한 건의 재현 명령과 확인 결과까지 말할 수 있어야 합니다.
3. 제출을 확정하고 Codex 사용을 멈춥니다. 서술형은 AI, 복사, 붙여넣기 없이 [QA_PREP](../QA_PREP.md)의 4문장 골격으로 씁니다.

## 정상이면
1. HOW_TO_USE의 명령을 실제로 실행한 기록이 있습니다.
2. 사건 로그의 커밋 해시가 `git log`에 모두 있습니다.
3. `git status`가 깨끗하고 `submit` 태그가 있습니다.
4. 셀프 질문 6개가 제 코드와 로그에서 나온 것입니다("일반적인 질문"이면 다시 만들어야 합니다).

## 아니면

문서와 코드가 어긋나는 곳이 많을 때(동결 후 수정 범위는 문서까지):

```
HOW_TO_USE.md와 AI_COLLABORATION.md에서 사실과 다른 문장을 모두 목록으로 만들어줘. 각 문장마다 '삭제 / 사실대로 수정 / 확인 후 유지' 중 하나를 제안해. 코드는 고치지 마.
```

설명이 안 되는 코드가 있을 때:

```
<파일>의 <함수>를 내가 설명할 수 있게 풀어줘. 입력, 처리 순서, 실패할 때의 동작, 이 방식을 택한 이유 순으로. 내가 이해하지 못하면 그 기능을 빼는 방법도 같이 알려줘.
```
