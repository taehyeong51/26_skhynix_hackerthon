# interview

담당자에게는 사용자가 직접 보낸다. 너는 복사용 문구만 만든다. 담당자는 구체적인 질문에만 답하는 경향이 있다.

## 질문 순서
해법 단어(웹앱, 최적화, 대시보드…)를 먼저 꺼내지 않는다.
1. 곤란했던 일: "최근 이 일 때문에 곤란했던 구체적인 상황 하나를 알려 주세요."
2. 현재 임시방편: 지금은 어떻게 처리하나.
3. 횟수·시간: 얼마나 자주, 한 번에 얼마나 걸리나, 규모(인원·건수).
4. 사용자·역할: 누가 쓰고, 누가 무엇을 보고 바꿀 수 있나.
5. 이번에 할 것 / 안 할 것.
6. 경계·예외: TASK.md 열린 질문에서 결과를 바꾸는 것부터.

## 규칙
- 한 질문에 사실 하나. 결과를 바꾸지 않는 질문은 만들지 않는다.
- 질문마다 Q번호와, 답에 따라 바뀌는 완료 조건 R번호를 붙인다.
- 사용자가 답을 붙여 주면 2~3줄로 요약해 TASK.md에 반영한다: 사실로 옮기거나, 가정을 확정·폐기. 대화 전체를 옮기지 않는다.
- 답이 없거나 모호하면 '가정'으로 남기고 근거를 적는다.
- 질문은 6~10개 안에서 끝낸다. 20분을 넘기면 남은 질문을 가정으로 돌린다.

## 합의문 (마지막)
아래 형식으로 복사용 문구를 만든다. 사용자가 보내고 확인받으면 TASK.md '합의' 칸에 날짜·시각과 함께 붙인다.

```
정리해 보면 이렇습니다. 맞는지 확인 부탁드립니다.
- 문제: …
- 만들 것: …
- 만들지 않을 것: …
- 성공 기준: …
- 제약: …
```
