# slice

입력: 슬라이스 이름 또는 R번호. 없으면 계획에서 다음 미완료 슬라이스.

1. 시작 선언: 이번에 바꿀 파일, 기대 동작, 확인 명령을 3줄로 쓴다. 기대값(예: 입력 X → 출력 Y, HTTP 200, 화면에 Z)을 구체 숫자·문자로.
2. 테스트 먼저: 실패하는 테스트 또는 확인 스크립트를 만들고 실제로 실패하는 것을 본다.
3. 구현: 필요한 최소 변경만. 범위 밖 정리·리팩터링은 하지 않는다.
4. 실행: 테스트와 확인 명령을 실제로 돌리고 출력 핵심을 그대로 보여 준다. 숫자는 손으로 한 번 검산한다. 실행된 테스트 수가 0이면 실패다.
5. 커밋: 통과한 것만. `git add <바꾼 파일>` 후 `git commit -m "<R번호> <슬라이스>: <확인 명령> 통과"`. push는 하지 않는다.
6. 기록:
   - 의미 있는 판단이 있었으면 docs/DECISIONS.md에 한 줄.
   - AI 제안을 고치거나 버렸으면 $collab-log 형식으로 AI_COLLABORATION.md에 한 건.
   - 실행법이 바뀌었으면 HOW_TO_USE.md 갱신.
7. 결과를 5줄 안으로 보고하고 멈춘다.

멈춤 규칙:
- 같은 실패가 2번이면 멈추고 '증상 / 가설 / 다음 시도'를 보고한다.
- 예상 시간의 2배를 넘기면 멈추고 범위를 줄일지 묻는다.
- 패키지가 없으면 설치하지 말고 표준 라이브러리·이미 있는 것으로 대안을 제시한다.
- 첫 E2E 슬라이스가 끝나면 사용자에게 Browser 확인 목록(로그인, 역할별 권한, 새로고침, 잘못된 입력, 핵심 버튼 연타)을 주고 결과를 받는다.
