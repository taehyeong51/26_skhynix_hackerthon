# plan

1. 슬라이스 목록: 첫 슬라이스는 '입력 → 핵심 규칙 → 출력'이 한 번 도는 최소 E2E. 이후 슬라이스는 완료 조건 하나씩. 각 슬라이스에 예상 시간(분)을 붙이고, 합계가 기능 동결 시각을 넘으면 뒤에서부터 '안 할 일'로 옮길 후보를 표시한다.
2. 매핑 표: `R번호 | 완료 조건 | 확인 방법(테스트 이름 또는 명령) | 슬라이스`. 확인 방법이 없는 조건은 만들지 않거나 확인 방법을 먼저 정한다.
3. 역할 매트릭스(역할이 2개 이상일 때): `역할 | 볼 수 있는 것 | 바꿀 수 있는 것`. 권한 검사는 화면이 아니라 처리 함수(API 핸들러)에서 한다. 권한 테스트를 매핑 표에 넣는다.
4. docs/FAILURE_MODES.md: 핵심 동작마다 5칸(정상 / 중복·동시 요청 / 제약 불충족 / 내부 계산·검증 실패 / 기존 적용 결과는 어떻게 되나)을 채운다. 기본 원칙은 '실패하면 기존 결과를 보존하고, 사용자에게 이유를 보여 준다'. 이 5칸 중 최소 정상·중복·실패는 테스트로 만든다.
5. 설계 결정(저장 방식, 프레임워크, 알고리즘, 캐시·재사용)은 docs/DECISIONS.md에 한 줄씩. 최적화·재사용이면 '기대는 가정 / 깨지는 입력 / 깨지면 어떻게 되돌아가나'를 반드시 쓴다.
6. 판정·계산·저장은 고정 코드로, LLM은 쓰지 않거나 문장 생성에만 쓴다.
7. 계획을 보여 주고 멈춘다. 사용자가 쳐낸 항목은 '안 할 일'로 옮긴다. 다음은 $slice.

과설계 금지: 4시간 과제다. 쓰이지 않을 추상화, 설정 체계, 플러그인 구조는 만들지 않는다.
