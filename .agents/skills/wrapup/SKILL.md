# wrapup

1. HOW_TO_USE.md 완성: 실행 방법(명령 그대로), 접속 주소·포트, 테스트 계정과 역할, 주요 화면 흐름(docs/SCREENS.md의 이동 흐름과 일치), 검증 경로(명령 하나·기대 출력·결과 요약), 구현 / 제외 / 가정 표, 알려진 한계. 적힌 명령은 지금 실제로 한 번 돌려서 맞는지 확인한다.
2. AI_COLLABORATION.md 점검: 사건 로그가 git log와 맞는지, 사용한 공개 자료(키트 레포 URL과 커밋 해시)가 적혔는지. 사실과 다른 문장은 고친다.
3. docs/DECISIONS.md·FAILURE_MODES.md에서 비어 있는 칸을 채우거나 '미확인'으로 표시.
4. 제출물 경계: `git status`와 파일 목록을 보여 주고, 과제와 무관한 파일(키트 원본, 임시 파일, 비밀값, 큰 데이터 복사본)이 없는지 확인한다. 숨김 폴더가 자동 제외된다고 가정하지 않는다.
5. 최종 커밋: `docs: 제출 문서 마무리`. `git status`가 깨끗한지, `git log --oneline`의 해시가 AI_COLLABORATION 사건 로그와 맞는지 확인한 뒤 `git tag -a submit -m "제출"`. 기능 동결 시각에 `freeze` 태그가 없으면 그 시점 커밋에 붙인다.
6. 셀프 질문 6개를 만든다. 내 산출물에서 나온 질문이어야 한다.
   - 범위·검증: 무엇을 구현했고 무엇을 뺐나, 평가자는 무엇으로 확인하나
   - 실패 경로: 핵심 동작이 중복 요청·제약 불충족·내부 실패일 때 어떻게 되나, 기존 결과는
   - 가정: 내 최적화·재사용이 기대는 가정과 그것이 깨지는 데이터
   - AI 협업: 사건 로그 한 건을 어떻게 파악·재현·수정했나, 무엇을 받아들이고 버렸나
   - 설계 이유 1개, 다음에 개선할 것 1개
   각 질문 아래에 답 골격만 준다(무엇 → 왜 → 어디서 깨지나 → 어떻게 확인했고 더 확인할 것). 완성 답안은 쓰지 않는다. 사용자가 자기 말로 말해 본다.
7. "제출 확정 뒤에는 AI를 쓰지 않습니다"라고 알리고 끝낸다.
